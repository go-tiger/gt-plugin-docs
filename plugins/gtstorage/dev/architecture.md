# 구조

GTStorage는 외부에 공개하는 API나 이벤트가 없습니다.

## 패키지

| 패키지                  | 역할                                                                                    |
| ----------------------- | --------------------------------------------------------------------------------------- |
| `dev.gotiger.gTStorage` | 메인 클래스 `GTStorage`. 구성 요소 조립, 자동 저장 작업 등록                            |
| `command`               | `/창고`, `/gtstorageadmin`                                                              |
| `database`              | SQLite 연결과 단일 DB 스레드(`DatabaseManager`)                                         |
| `gui`                   | `StorageHolder`(소유자 UUID, 페이지), 보관 금지 검사와 닫을 때 저장(`StorageListener`)  |
| `listener`              | 접속 종료 시 열린 창고 닫기                                                             |
| `storage`               | 열기, 닫기, 저장과 동시 접근 제어(`StorageManager`), 테이블 입출력(`StorageRepository`) |
| `util`                  | 아이템 직렬화, 메시지와 설정값                                                          |

## 창고 상태

`StorageManager`는 소유자 UUID 기준으로 두 가지 상태를 관리합니다.

| 필드           | 의미                                   |
| -------------- | -------------------------------------- |
| `openStorages` | 지금 열려 있는 창고 (UUID → Inventory) |
| `busy`         | 불러오는 중이거나 저장하는 중인 창고   |

둘 중 하나라도 해당하면 `open`과 `setrows`를 거부합니다. 그래서 한 창고를 두 사람이 동시에 열거나, 저장이 끝나기 전에
다시 열어서 예전 내용이 보이는 일이 없습니다.

## 열기와 저장

```
open()
  │  busy 등록
  ▼  DB 스레드: 줄 수 조회, 아이템 조회
  ▼  메인 스레드: Inventory 생성, openStorages 등록, busy 해제
  │
  ├─ 자동 저장 (auto-save-seconds마다) ──▶ 스냅샷 비동기 저장
  │
InventoryCloseEvent
  │  커서 아이템을 플레이어에게 반환
  │  openStorages 제거, busy 등록
  ▼  DB 스레드: 저장 후 busy 해제
```

- 저장은 해당 페이지의 행을 전부 지우고 다시 넣는 방식이며, 하나의 트랜잭션으로 묶습니다. 중간에 실패하면 롤백되어 기존
  내용이 남습니다.
- 불러오기에 실패하면(역직렬화 실패 포함) 빈 창고를 열지 않고 `storage-load-failed`를 보냅니다. 빈 창고를 열었다 닫으면
  기존 아이템을 빈 내용으로 덮어쓰기 때문입니다.

## 종료 처리

| 상황      | 처리                                                                                                                                                            |
| --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 접속 종료 | `PlayerQuitEvent`에서 창고가 열려 있으면 `closeInventory()`. 이벤트 순서에 기대지 않으려고 직접 닫음                                                            |
| 서버 종료 | `closeAllForShutdown()`: 열린 창고마다 커서 아이템을 반환하고, 창을 닫고, **메인 스레드에서 동기 저장**. 이때 `InventoryCloseEvent`로 인한 비동기 저장은 건너뜀 |

## 페이지

DB 스키마와 `StorageHolder`에 `page`가 있지만 지금은 항상 `0`만 씁니다. 여러 페이지 창고로 확장할 때를 위해 남겨 둔
것입니다.
