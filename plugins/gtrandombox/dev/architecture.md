# 구조

GTRandomBox는 외부에 공개하는 API나 이벤트가 없습니다. 원래 Skript로 만들었던 랜덤박스 스크립트를 Java로 옮긴
플러그인이라, 박스 파일의 YAML 키와 연출 타이밍을 원본과 같게 맞췄습니다.

## 패키지

| 패키지                    | 역할                                                                                              |
| ------------------------- | ------------------------------------------------------------------------------------------------- |
| `dev.gotiger.gTRandomBox` | 메인 클래스. 구성 요소 조립, 종료 시 설정 GUI 저장과 연출 엔티티 정리                             |
| `box`                     | `RandomBox`, `BoxReward`, 메모리 캐시(`BoxManager`), YAML 입출력(`BoxStorage`)                    |
| `command`                 | `/gtrandombox` (한글 서브커맨드)                                                                  |
| `gui`                     | 설정 GUI(자유 편집), 관리 GUI(클릭 취소, 표시용 복제본), 홀더, 리스너                             |
| `input`                   | 확률, 표시 이름 채팅 입력 대기(`ChatInputListener`)                                               |
| `item`                    | 박스 아이템 PDC 태그(`BoxItem`)                                                                   |
| `listener`                | 우클릭 개봉, 퇴장 시 개봉 상태 정리                                                               |
| `open`                    | 당첨 결정과 지급(`OpenService`), 룰렛 연출(`RouletteAnimation`), 동시 개봉 제한(`OpeningTracker`) |
| `util`                    | 아이템 직렬화, 메시지                                                                             |

## 박스 아이템 판별

지급할 때 박스 아이템에 PDC `gtrandombox:randombox = <박스 이름>`(STRING)을 심고, 우클릭할 때 이 값만 봅니다. 원본
스크립트는 아이템 이름으로 판별해서 모루로 이름을 바꾸면 위조할 수 있었는데, 이 방식으로 막았습니다.

## 개봉 흐름

```
우클릭 (메인 손)
  │  PDC에서 박스 이름 읽기 → 아이템, 블록 상호작용 취소
  ▼
OpenService.open()
  │  보상, 빈칸, 동시 개봉 확인
  │  유효 가중치 계산 → 가중치 추첨으로 당첨 결정
  │  박스 1개 차감, "개봉" 로그
  ▼
RouletteAnimation.play()  (매 틱 BukkitRunnable)
  │  교체 루프 → 폭발, 불꽃, 소리 → 회전 루프
  ▼  콜백
give(): 지급 (빈칸 없으면 드롭), 결과 메시지, "지급완료" 로그
```

당첨은 연출 전에 정해지고, 박스도 연출 전에 사라집니다. 서버가 꺼져 연출이 끊긴 경우를 위해 "개봉" 로그를 먼저 남깁니다.

## 유효 가중치

`computeEffectiveWeights()`가 확률 0인 보상의 가중치를 채웁니다.

- 확률을 정한 보상은 그 값을 그대로 씁니다.
- 0인 보상은 `100 - (정한 값의 합)`을 개수로 나눠 받습니다. 나머지는 앞쪽부터 1씩 더합니다.
- 정한 값이 없으면 100을, 합이 100 이상이면 0을 나눕니다. 가중치가 0인 보상은 추첨에서 빠집니다.

추첨은 `random.nextInt(total) + 1`을 누적합과 비교합니다.

## 연출

- `ItemDisplay`를 플레이어 앞에 소환하고, PDC `roulette-display`로 표시합니다.
- 교체 간격은 횟수 구간별로 1~8틱입니다.
- 회전은 매 틱 yaw를 `spin-degree`만큼 바꿔 `teleport`합니다.
- 불꽃은 소환 직후 `detonate()`해서 피해를 주지 않게 합니다.
- 플레이어가 나가거나, 월드를 옮기거나, 디스플레이가 사라지면 연출을 멈추고 콜백을 바로 호출합니다.
- 서버 시작과 종료 시 `roulette-display` 태그가 있는 `ItemDisplay`를 모두 지웁니다.

## 설정 GUI 저장

- 닫을 때 54칸을 읽어 저장합니다. 빈 칸은 그 슬롯의 확률과 표시 이름까지 지웁니다.
- 아이템이 있는 칸은 기존 확률과 표시 이름을 유지합니다. 그래서 아이템을 바꿔 넣어도 확률은 그대로입니다.
- 서버 종료로 창이 강제로 닫히는 경우에도 저장하도록 `onDisable`에서 직접 처리합니다.

## 채팅 입력

`AsyncPlayerChatEvent`(LOW)를 취소해 입력을 가로챕니다. 비동기 이벤트라 메시지 전송과 GUI 재오픈은 메인 스레드로
넘깁니다. 대기 상태는 메모리에만 있고, 퇴장이나 시간 초과 시 지워집니다.
